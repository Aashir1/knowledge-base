## 1. `useState`

### Core question

> **How does a component remember information between renders?**

Mental model:

```text
Normal variable
    ↓
lost/recreated on render

useState
    ↓
React remembers the value
    ↓
state update
    ↓
re-render
```

### Learn

* State vs normal variables
* Initial state
* Updating state
* Functional state updates
* State batching
* State updates are scheduled
* State immutability
* Objects/arrays in state
* Lazy initial state
* Why state updates don't immediately change the current variable

### Interview focus

> Why doesn't `setState()` immediately change the current state variable?

# 3. `useMemo`

### Core question

> **How can I avoid repeating an expensive calculation?**

Mental model:

```text
render
  ↓
expensive calculation
  ↓
result

useMemo
  ↓
remember result
  ↓
reuse until dependencies change
```

Example:

```tsx
const filteredUsers = useMemo(() => {
  return users.filter(user => user.active);
}, [users]);
```

### Learn

* Memoization
* Dependency array
* Referential equality
* Expensive calculations
* When `useMemo` helps
* When `useMemo` is unnecessary
* `useMemo` is an optimization, not a correctness mechanism

### Interview focus

> **When should you NOT use `useMemo`?**

# 4. `useCallback`

### Core question

> **How can I keep the same function reference between renders?**

Mental model:

```text
Every render
     ↓
new function object
     ↓
new reference
```

`useCallback`:

```text
render
  ↓
useCallback
  ↓
same function reference
  ↓
until dependencies change
```

Example:

```tsx
const handleClick = useCallback(() => {
  setCount(count + 1);
}, [count]);
```

### Learn

* Function identity
* Referential equality
* Why functions are recreated
* `React.memo` relationship
* Dependency array
* `useCallback` vs `useMemo`
* When `useCallback` makes things worse/unnecessary

### Interview focus

> **Why would passing an inline function cause a memoized child to render?**

# 5. `useRef`

### Core question

> **How do I remember something between renders without causing a re-render?**

Mental model:

```text
useState
   ↓
remember value
   ↓
update → re-render


useRef
   ↓
remember value
   ↓
update → NO re-render
```

Example:

```tsx
const countRef = useRef(0);

countRef.current++;
```

### Learn

* `.current`
* Persistence across renders
* No re-render when `.current` changes
* DOM references
* Previous values
* Mutable values
* `useRef` vs `useState`

### Interview focus

> **Why would you use `useRef` instead of `useState`?**

# 6. `useReducer`

### Core question

> **What should I do when state logic becomes complicated?**

Mental model:

Instead of:

```text
component
  ↓
many setState calls
  ↓
complex state logic
```

Use:

```text
Action
  ↓
Reducer
  ↓
New State
```

Example:

```tsx
dispatch({ type: "ADD_ITEM" });
```

Then:

```text
Action
   ↓
Reducer
   ↓
State transition
```

### Learn

* Reducer
* Action
* Dispatch
* State transitions
* Complex state logic
* Multiple related state values
* `useReducer` vs `useState`

### Interview focus

> **When would you choose `useReducer` instead of multiple `useState` calls?**

# 7. `useContext`

### Core question

> **How can components access shared data without passing props through every level?**

Without Context:

```text
App
 ↓
Parent
 ↓
Child
 ↓
GrandChild
 ↓
User
```

Props have to travel through every level.

With Context:

```text
        Provider
           │
     ┌─────┼─────┐
     ↓     ↓     ↓
   Child  Child  Child
     │
     ↓
  Consumer
```

### Learn

* Context
* Provider
* Consumer
* `useContext`
* Prop drilling
* Context re-renders
* Context vs global state
* When Context is appropriate

### Interview focus

> **Is Context a state-management library?**

# 9. `useDeferredValue`

### Core question

> **What if I already have a value, but the UI consuming it doesn't need to update immediately?**

Mental model:

```text
query
  ↓
LATEST VALUE
  ↓
input


query
  ↓
useDeferredValue
  ↓
DEFERRED VALUE
  ↓
expensive UI
```

Example:

```tsx
const deferredQuery = useDeferredValue(query);
```

### Learn

* Deferred values
* Rendering priority
* Temporary lag
* Expensive UI
* `useDeferredValue` vs debounce
* `useDeferredValue` vs `useTransition`

### Interview focus

> **What's the difference between `useTransition` and `useDeferredValue`?**

Memory trick:

```text
useTransition
     ↓
UPDATE

useDeferredValue
     ↓
VALUE
```

# 10. Custom Hooks

### Core question

> **How can I reuse stateful React logic between components?**

Instead of duplicating:

```text
Component A
 ├── state
 ├── effect
 └── logic


Component B
 ├── same state
 ├── same effect
 └── same logic
```

Extract:

```text
useSomething()
      ↓
Reusable React logic
```

Example:

```tsx
function useOnlineStatus() {
  // state + effect + logic
}
```

Then:

```tsx
const isOnline = useOnlineStatus();
```

### Learn

* What custom hooks are
* Rules of Hooks
* Extracting reusable behavior
* Sharing logic vs sharing state
* Custom hook composition
* When to create a custom hook
* When abstraction becomes unnecessary

### Interview focus

> **Do custom hooks share state between components?**

Important mental model:

```text
Custom Hook
     ↓
shares LOGIC
     ↓
not the same STATE
```

Each component calling the hook gets its own hook state.

# 🧠 Complete Hooks Mental Model

If you forget everything else, remember what **problem each hook solves**:

```text
useState
   ↓
"I need to remember state"


useEffect
   ↓
"I need to synchronize with something external"


useMemo
   ↓
"I don't want to recalculate this expensive value"


useCallback
   ↓
"I don't want this function reference to change"


useRef
   ↓
"I need to remember something without causing a render"


useReducer
   ↓
"My state logic is becoming complex"


useContext
   ↓
"I need to share data through the component tree"


useTransition
   ↓
"This state update isn't urgent"


useDeferredValue
   ↓
"This value doesn't need to update urgently"


Custom Hook
   ↓
"I want to reuse stateful React logic"
```
